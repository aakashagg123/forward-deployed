Recap

Transformers — recap & real-world examples

Real-world examples

The paper that started it (2017). Eight researchers, most of them at Google, published Attention Is All You Need. It dropped the recurrent networks that read text one word at a time and used attention alone. The block they described, attention plus a feed-forward layer, is the one in almost every language model today. 🎯 Takeaway: the shape has barely changed. Most progress since is scale, data, and the tricks in lesson 6.

Heads that copy (2022). Anthropic researchers studied small trained models and found attention heads with clear jobs. One kind looks at the previous token. Another finishes a repeated pattern. They linked these heads to how models learn from examples in the prompt. 🎯 Takeaway: attention does real, nameable work. But its weights are not a safe explanation of an answer, as Jain and Wallace showed.

Tiled attention (2022). The FlashAttention authors kept the exact same maths and changed where the numbers live. They process attention in small tiles in fast memory and never store the full score matrix. Models trained and served faster, and longer inputs became practical. 🎯 Takeaway: the score matrix is the cost of length. A kernel change cut it without changing the answer.

Sharing key and value heads (2023). The Llama 2 paper reports that its larger models use grouped-query attention, which shrinks the cache for keys and values. The motive was serving: a smaller cache means more requests per machine. 🎯 Takeaway: the cache sets concurrency. An architecture choice became a capacity choice.

Experts (2024). The Mixtral model uses 8 feed-forward experts and sends each token to 2. Its authors report about 47 billion parameters in total and about 13 billion in use for each token. 🎯 Takeaway: a model card has two sizes. One sets memory and the other sets compute.

Module recap

Lesson The one idea The question it makes you ask
The shape of a transformer Five numbers on a spec sheet give parameters, memory and compute What are the layers, width, heads, vocabulary and context, and what do they cost?
Attention Each token blends the values of the tokens it matches For our failures on long inputs, was the information missing or ignored?
The block Heads and feed-forward layers write notes into a shared stream, and the feed-forward layer holds two thirds of the weights Where was this model compressed, and what did we test?
Position and context Order must be added, and attention cost grows with the square of the length What do latency, cost and accuracy look like at our longest input?
Generation and the KV cache Keys and values are kept, so memory per request sets how many fit How many requests fit beside the weights at our context length?
Variants and the model card Total parameters set memory, active parameters set compute, and key and value heads set the cache What are total and active parameters and cache per token for each candidate?

The through-line. A transformer is a stack of one repeated block, and almost every question about it is a counting question. Count the parameters, then the multiply-adds, then the cache. Spec sheets hide four different sizes behind one name. The leaders who choose well turn the card into bytes and operations before they compare models.

Walk-away question: "For the model we plan to serve, can I state its total and active parameters, its cache per token, and how many requests fit on one machine at our context length?"

Test yourself

  1. GPT-2 small has 12 layers, a hidden size of 768, a vocabulary of 50,257 and 1,024 positions. About how many parameters does it have, and what share is in the embeddings?

    AnswerAbout 124 million: 124,439,808 by formula. The embeddings (tokens and positions) hold 39,383,808, which is 31.6%. (Lesson 1)

  2. In one block, which holds more parameters, attention or the feed-forward layer, and by how much?

    AnswerThe feed-forward layer. Attention has four matrices of d by d, which is 4d². The feed-forward layer has two matrices of d by 4d, which is 8d². So the feed-forward layer holds two thirds of a block. (Lesson 1)

  3. A team doubles a model's hidden size. What happens to the size of a block?

    AnswerIt multiplies by four, because block parameters grow with d². Doubling the number of layers only doubles it. (Lesson 1)

  4. What are queries, keys and values, in one sentence each?

    AnswerA query says what a token is looking for. A key says what a token offers. A value is what the token hands over when matched. (Lesson 2)

  5. Why are attention scores divided by the square root of the key length?

    AnswerA dot product of d_k numbers has variance proportional to d_k. Large scores push the softmax toward one-hot and its gradient toward zero. In the lesson's test at d_k = 256, the largest weight over 8 keys averages 0.92 without the scale and 0.34 with it. (Lesson 2)

  6. What does the causal mask do, and what goes wrong without it in training?

    AnswerIt sets the score for every later token to minus infinity, so those weights are zero. Without it, a token could read the one it is meant to predict, so training would look perfect and the model would fail when serving. (Lesson 2)

  7. Why can a new block be added to a trained model without breaking it?

    AnswerResidual connections add each part's output to its input. A block whose output matrices are zero returns its input exactly, so it starts as a no-op. (Lesson 3)

  8. A model is compressed, and it still passes short tests. Why test long, multi-step tasks?

    AnswerThe feed-forward layers hold most of the weights and much of the stored knowledge, so cuts there can lose rare facts. Long and multi-step tasks use many layers in sequence and expose small losses that short tests hide. (Lesson 3)

  9. At what input length does attention start to cost more than the rest of a block, for a hidden size of 4,096?

    AnswerAt about 6 times the hidden size, which is 24,576 tokens. Attention costs 2n²d multiply-adds and the rest costs 12nd², so they are equal at n = 6d. This assumes a feed-forward width of 4d. (Lesson 4)

  10. A vendor says a model supports 128,000 tokens. What do you ask?

    AnswerWhat latency, cost and accuracy are at that length, with the answer at the start, middle and end. Whether the limit is native or extended. And whether the serving stack uses tiled attention. A full score matrix at 131,072 tokens, 32 heads and 16-bit numbers would take 1 TiB per layer. (Lesson 4)

  11. What does a KV cache hold, and what is its size?

    AnswerOne key and one value vector for each token in each layer. The size is 2 × layers × key-value heads × head size × tokens × bytes per number. For a 7B-class shape (32 layers, 32 heads of 128) at 8,192 tokens and 16-bit, that is 4.0 GiB per sequence. (Lesson 5)

  12. Why is decode limited by memory speed and prefill by compute?

    AnswerDecode makes one token per pass, so each 2-byte weight does one multiply-add: about 1 FLOP per byte. Prefill over 512 tokens reuses each weight 512 times: about 512 FLOPs per byte. (Lesson 5)

  13. One card has 32 key and value heads and another has 8, all else equal. What changes in serving?

    AnswerThe cache per token falls to a quarter. On an 80 GiB accelerator in the lesson's example, 16 long requests fit with 32 heads and 68 with 8, which also trims the weights a little. (Lesson 6)

  14. A mixture-of-experts model has 47 billion total and 13 billion active parameters. What does each number set?

    AnswerTotal parameters set the memory needed to hold the weights. Active parameters set the compute per token. It needs the memory of a 47 billion model and computes like a 13 billion one. (Lesson 6)
